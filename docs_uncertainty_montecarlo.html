Uncertainty Monte Carlo Tab

Implemented in uncertainty_analyzer\tabs\uncertainty_montecarlo_tab.py and rendered through the shared uncertainty_sampling_tab.py workspace builder, the Monte Carlo Simulation tab is the primary probabilistic fault-stability analysis environment within the FracSTAT Uncertainty Analyzer. It lets a structural geologist, geomechanical engineer, or reservoir engineer propagate measurement and interpretation uncertainty in stress magnitudes, rock-strength parameters, pore pressure, and fault orientation through a deterministic Mohr–Coulomb fault-stability calculation, producing a fully probabilistic characterization of slip tendency, dilation tendency, fracture susceptibility, and Coulomb failure potential for one or many faults simultaneously.

Unlike a conventional deterministic geomechanical assessment — which assigns a single value to each input parameter and returns a single stability verdict — the Monte Carlo tab treats every geomechanical input as a random variable governed by a user-selected probability distribution. Thousands of independent realizations of the fault–stress system are drawn, each realization is passed through the same physical stability equations used elsewhere in FracSTAT, and the resulting population of outcomes is summarized statistically — yielding defensible, quantifiable answers to questions such as "what is the probability that this fault will fail under current reservoir conditions?" rather than a single pass/fail label that hides the underlying uncertainty.

Because uncertainty_montecarlo_tab.py itself is a thin dispatcher — it sets sampling_method="mc" and immediately delegates construction of the entire tabbed workspace to UncertaintySamplingTab.build() — this guide documents the complete Monte Carlo workflow as experienced by the user, including the six analysis sub-modules that appear as nested tabs beneath "Monte Carlo Simulation": Geomechanics, Statistics, Sensitivity, Visualization, Spatial Probability Map, and Validation & Export. Each of these sub-modules operates on the same underlying Monte Carlo realization set and is therefore an integral part of the Monte Carlo analysis, even though its implementation is factored into separate source files for maintainability.

1. Purpose and Scope

1.1 Intended Audience

  • Structural geologists and geomechanical analysts performing fault-reactivation and induced-seismicity risk screening.
  • Reservoir engineers evaluating injection- or depletion-induced pore-pressure changes on pre-existing faults.
  • Geohazard and CO₂-storage risk assessors requiring probabilistic, auditable slip- and dilation-tendency estimates.
  • Software QA engineers and technical reviewers validating the scientific correctness of FracSTAT outputs.

1.2 Document Conventions

Throughout this guide, variable names shown in the mathematical background sections correspond directly to the internal computational quantities used by the module (e.g. σ1, σ2, σ3 for the major, intermediate, and minor principal stresses). GUI labels are reproduced exactly as they appear on screen and are set in bold. Equation numbers are provided for cross-referencing between the Mathematical Background (Section 6) and the Algorithms (Section 7).

2. Position within the FracSTAT Architecture

The Uncertainty Analyzer is one of three principal analysis workspaces in FracSTAT, alongside the Static Analyzer and the Dynamic Analyzer. Unlike those two workspaces, which operate on deterministic fracture-trace geometry digitized from an image or SVG, the Uncertainty Analyzer is intentionally decoupled from image-based tracing: its input is a tabular Excel/CSV data set describing one or more fault planes and their associated geomechanical properties. The workspace header therefore disables the "Load SVG", "Scale", and "Trace Map" controls and enables only "Load Excel", reflecting this different, tabular data model.

The Monte Carlo tab and its sibling, the Latin Hypercube Sampling (LHS) tab, are the two sampling-method entry points into an otherwise identical analysis pipeline. Both are thin wrappers around the shared UncertaintySamplingTab.build() routine, differing only in the string passed for sampling_method ("mc" or "lhs"), which is later resolved by the sampling engine into a specific pseudo-random-number generation strategy (see Section 7.1). Every other element of the workspace — the input-loading logic in uncertainty_app.py, the fault-preparation and column-alias resolution in sampling_engine.py, the physical stability equations in uncertainty_calculator.py, and the six analysis sub-tabs — is shared code, so a Monte Carlo run and an LHS run for the same input data and settings are directly comparable and, at sufficiently large sample sizes, should converge to the same statistical answer.

3. Interface Overview

Selecting the Monte Carlo Simulation tab presents a two-level tabbed interface. The outer level (Monte Carlo Simulation vs. Latin Hypercube Sampling) selects the sampling method; the inner level presents the six analysis sub-modules described below. All six sub-modules read from the same shared context dictionary (the context object created once per outer tab in UncertaintySamplingTab.build), so a single simulation run populates every sub-module simultaneously, and only the currently visible sub-module's plot is redrawn at any moment for responsiveness (see Section 12.2).

4. Data Input and Preprocessing

The Monte Carlo tab consumes tabular fault data loaded through the workspace header's Load Excel control, handled by _load_excel_file / _read_uncertainty_input_file in uncertainty_app.py. Loading occurs on a background thread so the Tk event loop remains responsive, with a full-screen loading overlay shown while the file is parsed.

4.1 Supported File Types

  • .csv — read directly with pandas.read_csv.
  • .xlsx / .xls — opened with pandas.ExcelFile; if the workbook contains more than one worksheet, a modal Select Worksheet dialog is presented (single-sheet workbooks load automatically with no prompt).

4.2 Column Alias Resolution

Column names in real-world spreadsheets are inconsistent ("Sigma 1" vs. "Sigma1" vs. "σ_1"). The module normalizes every header by lower-casing it, replacing non-alphanumeric characters with spaces, and collapsing repeated whitespace (_normalise_name), then matches the normalized header against a registry of accepted aliases (_COLUMN_ALIASES) for each logical field. This makes column matching case-insensitive and tolerant of spacing/punctuation differences.

4.3 Validation Rules Applied at Load Time (prepare_faults)

  • Strike and Dip columns are mandatory; their absence raises an explicit error identifying which column is missing.
  • Strike and Dip are coerced to numeric with pandas.to_numeric(errors="coerce"); any resulting NaN triggers a validation failure listing that Strike/Dip must be finite for every row.
  • Strike must satisfy 0 ≤ Strike < 360°; Dip must satisfy 0° ≤ Dip ≤ 90°.
  • If a Fault ID column is present, IDs are cast to string, whitespace-trimmed, and checked for blank or duplicate values; either condition raises an error before any sampling can begin.
  • If a Fault ID column is absent, sequential integer identifiers (1, 2, 3, …) are assigned automatically.
  • Optional columns (sigma1, sigma2, sigma3, friction, cohesion, pore_pressure, shmax) are coerced numeric where present; when absent for a given fault, the corresponding sidebar mean value in the Geomechanics tab is used instead.
Note: when no file has been loaded at all, prepare_faults(None) returns a single synthetic "Representative plane" fault (Strike = 45°, Dip = 60°), which lets a user explore the tool's mechanics using only the global mean/SD values entered in the Geomechanics sidebar before any real fault population is available.

4.4 Fault Selector and the All Faults / Single-Fault Duality

Every sub-tab shares one fault_selection_var. Selecting All Faults samples every loaded fault at the configured sample size and concatenates the results into one realization table tagged by fault_id; selecting an individual fault restricts the Strike/Dip/stress means to that fault's row and (if orientation fields are otherwise blank) draws the given number of realizations for that fault alone. To avoid redundant computation, an All Faults run is also cached per individual fault: selecting a single fault after an All Faults run instantly slices the cached population for that fault_id rather than re-running the sampler (see Section 12.1).

5. Settings and Controls

The Geomechanics sub-tab is where every stochastic input to the Monte Carlo simulation is configured. Its sidebar is organized into four numbered cards presented top-to-bottom in the recommended workflow order: stress regime, principal stresses, rock strength/fluid pressure, and fault/stress orientation, followed by the effective-stress toggle.

5.1 Stress Regime Selector

A single dropdown selects which principal stress is assumed vertical (Sv), following the Andersonian classification of faulting regimes. This selection does not alter the sampled σ1 > σ2 > σ3 ordering used for display and statistics; it only controls how those three sampled stresses are remapped onto the fault-normal stress calculation performed by calculate_fault_stability (see Section 6.4 and Section 7.4).

Strike-Slip (Sv = S2)strike_slipσ2 (intermediate) is vertical; remapped into the σ3 slot.
Reverse/Thrust (Sv = S3)reverseσ3 (smallest) is vertical; this is the calculator's native convention and requires no remap (default).

5.2 Principal Stress Inputs (Card 1)

Sigma 1, Sigma 2, and Sigma 3 (MPa) are each configured with an independent Mean, Standard Deviation (STDV), and Distribution Type. Because the sampler represents the stress tensor as an ordered base stress (σ3) plus two non-negative gaps (σ2−σ3 and σ1−σ2; see Section 7.2), the engine enforces two structural constraints at run time:

  • Mean ordering: Sigma 1 (mean) > Sigma 2 (mean) > Sigma 3 (mean) > 0.
  • Standard-deviation ordering: SD(Sigma 1) ≥ SD(Sigma 2) ≥ SD(Sigma 3), required for the gap-variance decomposition to remain non-negative.

Available distribution choices for the principal stresses are Normal, Truncated Normal, Gaussian (alias of Normal), Log Normal, and Gamma — all positive-support laws appropriate for physical stress magnitudes. An Auto STDV control lets the user set all three principal-stress standard deviations simultaneously as a chosen percentage (1–50%) of their respective means.

Strike, Dip, and SHmax Azimuth (all in degrees) are angular quantities and are therefore sampled with circular statistics rather than a linear Normal/Truncated-Normal law. 5.5 Effective Stress Toggle

The Use effective principal stresses switch controls whether pore pressure is subtracted from the normal stress (and from σ1, σ3 in the dilation-tendency formula) before computing every stability metric. Toggling this switch after a run has completed does not require re-sampling: it recomputes Ts, Sf, Fs, Td, and the failure flag for the already-sampled realizations in place (see Section 8.4), and refreshes every open plot and the validation report's metadata to reflect the new basis.

6. Mathematical Background

This section defines, with explicit notation, every equation evaluated by the Monte Carlo engine for a single realization. All equations are applied identically and independently to each of the N sampled realizations for each selected fault, so the outputs described here should be read as per-realization formulas whose ensemble, across all N draws, constitutes the Monte Carlo result population.

6.2 Fault-Normal Vector and Resolved Stress

The unit vector normal to the fault plane is constructed from its strike and dip using the standard structural-geology right-hand-rule convention:

n = ( −sin(dip)·sin(strike), sin(dip)·cos(strike), −cos(dip) ) (Eq. 6.1)

Because the calculator's internal (rotated_x, rotated_y) coordinate frame is aligned with SHmax rather than geographic north, the normal vector is rotated about the vertical axis by the sampled SHmax azimuth before the stress tensor is resolved:

rotated_x = cos(SHmax)·nx + sin(SHmax)·ny rotated_y = −sin(SHmax)·nx + cos(SHmax)·ny (Eq. 6.2)

With the three sampled principal stresses assumed to act along the rotated_x, rotated_y, and vertical (z) axes respectively (reverse/thrust convention; see Section 6.4 for the regime remap), the normal and total resolved (traction) stresses are:

σn = σ1·rotated_x² + σ2·rotated_y² + σ3·nz² (Eq. 6.3) |T|² = σ1²·rotated_x² + σ2²·rotated_y² + σ3²·nz² (Eq. 6.4) τ = √ max(|T|² − σn², 0) (Eq. 6.5)

The max(·, 0) clamp in Equation 6.5 is a numerical safeguard against a negative radicand arising from floating-point rounding when the traction magnitude is very close to the normal-stress magnitude (i.e. near-zero shear).

6.3 Effective Stress and the Stress Basis Toggle

Effective normal stress follows Terzaghi's principle:

σ'n = σn − Pp (Eq. 6.6)

The module maintains both bases simultaneously for every realization; the Use effective principal stresses switch (Section 5.5) selects which of σn or σ'n, and which of the raw or pore-pressure-adjusted σ1/σ3, feed into the Ts, Td, Sf, and Fs formulas below. When effective stress is disabled, pore pressure is excluded entirely from these four metrics (a conservative total-stress assessment); when enabled, it is subtracted throughout (an effective-stress assessment appropriate for injection/depletion-induced fault-reactivation studies).

6.4 Stress-Regime Remap

The stability calculator's fixed internal convention places the vertical stress in the σ3 (normal_z) slot. Because the sampler always returns σ1 > σ2 > σ3 for display purposes, the module remaps which sampled value is fed into that slot according to the user-selected stress regime, without altering the display ordering:

6.5 Slip Tendency (Ts)

Slip tendency (Morris, Ferrill & Henderson, 1996) is the ratio of resolved shear stress to resolved normal stress on the fault plane, evaluated on the selected stress basis (σn or σ'n):

Ts = τ / σn(basis) (Eq. 6.7)

Ts is undefined (reported as missing) when the basis normal stress is not strictly positive. Higher Ts indicates a fault plane oriented closer to the frictional failure envelope for the current stress state; Ts values approaching or exceeding the effective friction coefficient signal elevated reactivation risk.

6.6 Dilation Tendency (Td)

Td = (σ1(basis) − σn(basis)) / (σ1(basis) − σ3(basis)) (Eq. 6.8)

Td quantifies the propensity of a fault or fracture to open (dilate) under the current stress field, independent of frictional sliding. It is bounded in [0, 1] for physically consistent stress states: Td = 1 corresponds to a plane oriented for maximum dilation potential (the least favorably clamped orientation), while Td = 0 corresponds to a plane subjected to the maximum principal stress directly across it. Dilation tendency is calculated in sampling_engine.py using the true global maximum and minimum principal stresses (σ1 and σ3 as sampled, i.e. before the regime remap of Section 6.4), since it is defined against the overall stress ellipsoid, not against whichever slot a given regime happens to place Sv in.

6.7 Fracture Susceptibility (Sf)

Sf = σn(basis) − (τ − C0) / μ (Eq. 6.9)

Sf expresses, in stress units (MPa), the margin between the current normal stress and the normal stress at which the Mohr–Coulomb failure criterion τ = C0 + μ·σn(basis) would be satisfied for the same shear stress and friction/cohesion values. Sf ≤ 0 indicates the realization has crossed the failure envelope (see Section 6.9); Sf therefore doubles as both a continuous risk metric and the basis for the binary failure classification.

6.8 Coulomb Failure Index (Fs / Fsi)

Fs = τ / (C0 + μ·σn(basis)) (Eq. 6.10)

Fs (displayed on plots using the scientific symbol Fsi to avoid confusion with the general variable "Fs") is a normalized failure-potential ratio: Fs = 1 marks the Mohr–Coulomb failure envelope exactly, Fs < 1 denotes a stable stress state, and Fs > 1 denotes a stress state that has exceeded frictional-cohesive strength on that plane. Fs is undefined when the basis normal stress or the failure-envelope denominator is not strictly positive.

6.9 Binary Failure Flag

failure = TRUE if and only if Sf ≤ 0 (Eq. 6.11)

This nullable boolean column underlies the Probability of Failure statistic reported throughout the Geomechanics, Statistics, and Validation & Export sub-tabs (Section 9).

6.10 Analytical Reference Cases

Two closed-form sanity checks are embedded permanently in the validation pipeline (validation.analytical_benchmarks) and are re-evaluated on every run:

  • Sigma-3 principal plane (strike = 0°, dip = 0°): the fault normal is exactly parallel to σ3, so the analytically expected normal stress equals σ3 (25 MPa in the reference case) and the expected shear stress is exactly zero.
  • Sigma-1 principal plane (strike = 90°, dip = 90°): the fault normal is exactly parallel to σ1, so the expected normal stress equals σ1 (60 MPa) with zero shear.

Both cases additionally check the analytically expected dilation tendency (1.0 and 0.0 respectively) and fracture susceptibility, with a numerical tolerance of 1×10⁻¹⁰. This is a unit-test-grade verification, embedded in the production workflow, that the vectorized fault-normal geometry and stress-resolution code (Section 6.2) has not been silently broken by a code change.

7. Sampling Algorithms

This section documents the algorithmic pipeline implemented in sampling_engine.py that transforms user-configured distributions into a validated, physically consistent ensemble of realizations, specifically as it is invoked with method="Monte Carlo Simulation" (kind="mc").

7.1 Random Number Generation: Monte Carlo vs. Latin Hypercube

The function _standard_samples() is the single point where the two sampling methods diverge. For Monte Carlo, it uses NumPy's modern Generator API seeded from the user's integer seed (numpy.random.default_rng(seed)) to draw an (N × D) array of independent standard-normal variates, where N is the requested sample count and D is the number of stochastic dimensions (7 stress/strength/orientation inputs from INPUTS plus 2 fault-orientation inputs from ORIENTATION_INPUTS = 9 total dimensions per realization).

Z ~ N(0, I_D), Z ∈ R^(N×D) (Eq. 7.1, Monte Carlo)

For comparison, Latin Hypercube Sampling instead draws a D-dimensional Latin Hypercube design over the unit cube via scipy.stats.qmc.LatinHypercube(seed=seed), clips the resulting uniform coordinates away from exactly 0 or 1 (to avoid infinite values under the inverse-CDF transform), and maps them to standard-normal space with the inverse normal CDF (scipy.stats.norm.ppf). Monte Carlo sampling therefore explores the input space with independent pseudo-random draws, while LHS enforces stratified, evenly spaced coverage along each marginal dimension — typically converging with fewer realizations, at the cost of slightly more complex generation. Because the Monte Carlo tab always resolves to kind="mc", every subsequent transformation in this section operates on the independent standard-normal array Z.

7.2 Ordered Principal-Stress Sampling via Positive Gaps

Sampling σ1, σ2, σ3 as three independent random variables cannot, by construction, guarantee σ1 > σ2 > σ3 on every realization. The engine instead samples the smallest stress (σ3) directly and represents the other two as σ3 plus two independently distributed, strictly non-negative gaps:

σ3 ~ Distribution_3(mean3, sd3), support [0, ∞) gap23 ~ Distribution_2(mean2 − mean3, sd2′), support [0, ∞) gap12 ~ Distribution_1(mean1 − mean2, sd1′), support [0, ∞) σ2 = σ3 + gap23, σ1 = σ3 + gap23 + gap12 (Eq. 7.2)

where the gap standard deviations are derived by variance subtraction so that the marginal variance of each reconstructed principal stress still matches the user-specified SD:

sd2′ = √ max(sd2² − sd3², 0) sd1′ = √ max(sd1² − sd2², 0) (Eq. 7.3)

This construction is exactly why the engine requires SD(σ1) ≥ SD(σ2) ≥ SD(σ3) at run time (Section 5.2): if the ordering were violated, the radicand in Equation 7.3 would go negative and silently clamp to zero, producing an incorrect (deflated) gap variance. Each of the three quantities (σ3, gap23, gap12) is drawn using its own selected distribution family (Section 7.3) applied to its own dedicated column of the standard-normal array Z (columns 2, 1, and 0 respectively, converted to a uniform coordinate via the standard-normal CDF before being handed to the distribution transform).

7.3 Distribution Registry and the Inverse-CDF (Quantile) Method

Every scalar stochastic input (other than orientation) is transformed from a unit-uniform coordinate u = Φ(z) via the appropriate quantile function of the chosen distribution (distributions.sample_scalar). All distributions except Uniform are moment-parameterized (mean, standard deviation) so that a user need not learn each law's native shape/scale parameters.

A defensive post-sampling check (in sample_scalar) verifies that no drawn value for a bounded quantity falls outside its declared physical range; a violation raises an explicit error rather than allowing an unphysical realization to silently propagate into the stability calculation.

7.4 Automatic Truncation of Normal/Gaussian Selections

A subtle but important behavior: whenever the user selects Normal or Gaussian for an input that carries a finite physical bound (friction ∈ [0,1]; cohesion, pore pressure, and all three principal stresses ≥ 0), the sampler transparently substitutes the mathematically equivalent Truncated Normal distribution with the same mean and standard deviation, rather than allowing probability mass to fall outside the physical range. This substitution is recorded in the results' metadata (results.attrs["effective_distributions"], surfaced via distributions.effective_distribution_name) and is reported explicitly to the user in the post-run status message and in the exported reproducibility metadata, so that a "Normal" label the user selected in the UI never silently misrepresents what was actually sampled.

7.5 Orientation Sampling: Von Mises and Fisher 3D Models

SHmax azimuth is always sampled with a circular Von Mises distribution about its mean using its own concentration k_shmax:

SHmax = [ VonMises.ppf(u; k_shmax, loc=mean_SHmax) in radians ] × (180/π), reduced modulo 360° (Eq. 7.4)

For fault-plane orientation (Strike, Dip), two mutually exclusive models are available, selected by the Orientation Distribution dropdown:

7.5.1 Von Mises (independent strike and dip)

  • Strike is sampled circularly with the Von Mises law (Equation 7.4 form) using k_strike about the fault's own mean strike.
  • Dip is sampled with a Truncated Normal law bounded to [0°, 90°], whose standard deviation is approximated from k_dip via the small-angle Von Mises variance relation σ≈(180/π)/√k (with a diffuse 90° spread used when k_dip = 0).

7.5.2 Fisher 3D (coupled strike and dip)

The Fisher 3D model recognizes that strike and dip are not physically independent — they jointly describe a single plane's pole vector — and instead samples a 3-D Fisher distribution of unit vectors clustered about the mean pole direction, using the shared Strike-row k as the Fisher concentration κ:

cos(θ) = 1 + ln[ u1 + (1−u1)·e⁻²ᵀ ] / κ (or 1−2u1 when κ = 0) φ = 2π·u2 (Eq. 7.5)

The polar angle θ and azimuthal angle φ are used to rotate about the mean pole direction within a local (east, north) tangent frame constructed by Gram-Schmidt orthogonalization against a reference axis. Because a geological plane is axial (a pole and its antipode describe the same plane), any sampled pole with a positive vertical component is reflected to the lower hemisphere (poles[poles[:, 2] > 0] *= -1.0) before back-converting to a strike/dip pair. Horizontal planes (dip ≈ 0) retain the fault's original mean strike convention, since strike is geometrically undefined for a perfectly horizontal surface.

The practical distinction: Von Mises treats strike uncertainty and dip uncertainty as unrelated "wobbles" about the mean orientation, appropriate when strike and dip were measured or interpreted independently (e.g. from two separate uncertain picks); Fisher 3D instead treats the entire plane orientation as one uncertain 3-D direction, appropriate when the orientation as a whole (e.g. from a single dipmeter or borehole-image interpretation) carries a combined angular uncertainty.

7.6 All Faults vs. Single-Fault Sampling Loop

generate_samples() iterates once per row of the prepared fault table (Section 4.3). For each fault it draws a fresh D-dimensional standard-normal block via _standard_samples, transforms it into physical stress/strength/orientation values via _sample_inputs (Sections 7.2–7.5), applies the selected stress-regime remap (Section 6.4), evaluates the deterministic stability physics (Sections 6.2–6.9) via calculate_fault_stability, and appends fault_id and a zero-based realization index column before concatenating every fault's realization block into one combined DataFrame. Cancellation is checked between faults (and once before/after the standard-normal draw) via a threading.Event, so a long multi-fault run can be interrupted promptly without corrupting partially completed results.

A critical detail governing whether orientation is sampled per-fault or globally is the use_global_orientation flag, which is TRUE only when no fault data has been loaded at all (the synthetic representative-plane case). Whenever real fault data is present, each fault's own Strike/Dip mean (from its spreadsheet row) is used as the orientation-sampling center, ensuring that the All Faults population correctly reflects each fault's individual measured orientation rather than one shared global mean.

8. Internal Workflow and Execution Pipeline

This section traces the complete sequence of events from the moment a user clicks Run Monte Carlo Simulation to the moment results are displayed, as implemented by the run() closure inside UncertaintySamplingTab.build().

8.1 Input Validation Stage

  • SAMPLES is parsed as an integer and checked against the inclusive range [10, 100,000].
  • SEED is parsed as an integer (any integer, including negative, is accepted).
  • For every stochastic input, the mean and SD entry fields are parsed as floats; a non-negative SD is enforced individually for every parameter.
  • If a distribution is set to Uniform or Beta and explicit Min/Max bound fields have been filled in, those bounds are parsed and validated as numeric before being attached to that input's settings dictionary.
  • Each orientation concentration k (Strike, Dip, SHmax rows) is parsed as a finite, non-negative float.
  • In All Faults mode, if the Strike/Dip mean fields are blank (their normal state in that mode), the last remembered global mean value is substituted so the representative-plane fallback still has a usable value.

Any validation failure raises a ValueError that is caught and displayed via a modal Invalid uncertainty settings error dialog; no worker thread is started and no existing results are disturbed.

8.2 Background Worker Thread and Progress Reporting

Once validation succeeds, the workspace switches the active module tab to the button that was clicked, disables every shared and per-module simulation control (SAMPLES, SEED, FAULT selector, and the Run button itself) to prevent concurrent runs, and shows a full-screen determinate progress overlay (Running uncertainty simulation…). A daemon threading.Thread is then started running the private _worker() function, which:

  1. Calls generate_samples() (Section 7), passing a cancel_event and a progress_callback that reports completed sampling stages (1 preparation stage + 2 stages per fault: sampling and stability calculation).
  2. If the cancel event is set immediately after sampling completes, raises SimulationCancelled without proceeding to validation, avoiding wasted computation on discarded results.
  3. Calls build_validation_report() (Section 9.4), passing a second progress_callback whose reported range is offset to continue smoothly from where sampling left off, so the single progress bar advances continuously through both phases.
  4. Marshals the completed results and validation report back onto the main Tk thread via app.after(0, _on_success, ...), since Tkinter widgets may only be touched from the main thread.

A floating, always-on-top Cancel window is displayed alongside the full-screen loader (which otherwise covers the in-tab Cancel button), giving the user a way to interrupt a long run at any time; clicking it sets the shared cancel_event, which is checked at each fault-loop boundary inside generate_samples.

8.4 Post-Run Recalculation: The Effective-Stress Toggle Path

Toggling Use effective principal stresses after a run does not re-invoke the sampler. Instead, apply_slip_tendency_basis() recomputes Ts, Sf, Fs, Td, and the failure flag directly on every cached realization DataFrame (both the currently displayed one and every other fault's cached result) using the already-sampled sigma1/sigma2/sigma3/pore_pressure/shear_stress/friction/cohesion columns, following exactly Equations 6.6–6.11 on the newly selected basis. It then refreshes the convergence table and its summary for the active result, updates the reproducibility metadata's analysis_options.use_effective_ts flag, redraws the active plot, marks the workspace dirty, and autosaves — all without discarding or resampling the underlying stochastic draws. This design choice keeps the (potentially expensive) sampling step decoupled from a purely presentational recalculation.

8.5 Autosave and Session Persistence

Loading an input file, switching workspaces, changing the active analysis sub-tab, and completing a run all trigger a private, silent autosave (via core.project_state.save_state / collect_uncertainty_state) that persists the current uncertainty session independently of the Static and Dynamic Analyzer workspaces — by design, the Uncertainty Analyzer's input and results are never written into the shared Static/Dynamic handoff cache, keeping the three workspaces' data fully isolated from one another.

9. Statistical Methods

This section describes every statistical computation available across the Statistics, Sensitivity, and Validation & Export sub-tabs, all of which operate on the realization population produced by the Monte Carlo run described in Sections 6–8.

9.1 Descriptive Statistics (Statistics Sub-Tab)

For the currently selected metric (Ts, Td, Sf, or Fs) or sampled input, the Statistics module computes and displays, in a compact grid of eight cards:

Four plot types are available: Metric Histogram (with a mean reference line and a shaded P10–P90 band), Sampled Input Distribution (histogram of any single stochastic input, annotated with its mean/SD or, for orientation inputs, its mean/k), Input-Response Plot (a dual-axis scatter of the chosen output metric against a chosen input, overlaid on that input's histogram on a secondary y-axis, with an optional response-trend curve), and Probabilistic Response (Single) (a histogram of one predefined input with the response trend overlaid on a twin axis and configurable independent Y1/Y2 axis limits).

The response trend line, computed in _plot_response_trend, supports three fitting methods: Binned mean (the input range is divided into histogram-matched bins and the mean response is plotted at each bin's mean input value — a non-parametric, assumption-free summary), Linear regression (a first-degree least-squares polynomial fit), and Quadratic regression (a second-degree least-squares polynomial fit for capturing curvature in the input-response relationship).

9.2 Per-Fault Statistics

per_fault_statistics() (statistics.py) groups the realization table by fault_id and computes, for each fault, the mean, median, standard deviation, and the P05/P10/P50/P90/P95 percentiles of the selected metric, joined with a Probability of Failure column equal to the fraction of that fault's realizations with Sf ≤ 0. This per-fault breakdown underlies the Fault Uncertainty Envelope and Fault Behaviour Classification plots in the Visualization sub-tab and the Spatial Probability Map's per-fault aggregation (Section 10.5).

9.3 Global Sensitivity Analysis (Sensitivity Sub-Tab)

The Sensitivity sub-tab quantifies how strongly each of the nine stochastic inputs (σ1, σ2, σ3, pore pressure, friction, cohesion, SHmax, strike, dip) influences a chosen output metric (Ts, Td, Sf, or Fs), using two complementary regression-based measures computed over the full realization set (or, when multiple faults are present, over the per-realization mean across all faults, so the sensitivity ranking reflects population-level rather than single-fault behavior).

9.3.1 Standardized Regression Coefficients (SRC)

Every input column and the output column are first standardized to zero mean and unit variance (dividing by the sample SD, with inputs having zero variance safely mapped to a zero contribution rather than a division-by-zero). An ordinary least-squares multiple regression is then fit via NumPy's numpy.linalg.lstsq:

y_std = β1·x1_std + β2·x2_std + ... + β9·x9_std + ε (Eq. 9.1)

Each fitted coefficient βi is the Standardized Regression Coefficient for input i: it measures the expected change in the output, in standard-deviation units, per one-standard-deviation change in that input, holding the (linear, additive) effect of the other inputs fixed. SRC assumes an approximately linear input-output relationship and is most reliable when the true response surface is not strongly nonlinear.

9.3.2 Partial Rank Correlation Coefficients (PRCC)

For each input, both the inputs and the output are first converted to average ranks (Spearman-style). A linear model of the remaining eight ranked inputs is fit against the ranked target input and, separately, against the ranked output; the residuals of both regressions are then correlated:

PRCC_i = corr( x_i_rank − x̂_i_rank , y_rank − ŷ_rank ) (Eq. 9.2)

PRCC measures the monotonic association between one input and the output after removing the linear influence of every other input on both quantities, making it more robust than SRC to mild non-linearity while still requiring monotonicity in the underlying relationship.

9.3.3 Tornado Diagram

Both SRC and PRCC are tabulated in a nine-row sidebar table and one is plotted as a horizontal tornado bar chart, sorted (per the Sort Direction control) by ascending magnitude, descending magnitude, or the input's natural physical ordering. Bars can be colored by a Colormap Gradient (scaled by each coefficient's magnitude relative to the largest), by Positive/Negative sign, or with a Single Color; numeric value labels can be toggled on or off, and a zero-reference vertical line is always drawn to visually separate destabilizing from stabilizing sensitivities.

9.4 Convergence Diagnostics

convergence_table() (validation.py) evaluates the running Ts mean, Ts P50, Ts P90, Sf mean, and probability-of-failure at a geometrically spaced sequence of nested sample-size checkpoints (between roughly 32 samples and the full requested sample count, in up to 6 steps), and records the increment between successive checkpoints for each metric. convergence_summary() then declares the run Passed only if every continuous metric's final increment is ≤ 2% of its own final value and the probability-of-failure's final increment is ≤ 1 percentage point; otherwise it is reported Not yet converged, signaling that a larger sample size may be warranted for that particular fault/settings combination.

9.5 Analytical Benchmarks and Reference Comparison

In addition to the two closed-form geometric benchmark cases described in Section 6.10, a three-case reference_comparison() independently re-implements the scalar (non-vectorized) version of the stability equations in pure Python/math and compares it point-by-point against the vectorized NumPy implementation used for the actual Monte Carlo ensemble, on both the total- and effective-stress bases. Any discrepancy above 1×10⁻¹⁰ would flag a numerical-implementation divergence between the two code paths; in normal operation this check always passes and exists as a continuous regression safeguard rather than a user-facing diagnostic.

9.6 Reproducibility Metadata

Every run's reproducibility_metadata() (validation.py) records, and later exports: an ISO-8601 UTC analysis timestamp; the sampling method and requested/actual samples per fault; the integer seed; the fault count and a SHA-256 hash of either the source file bytes or a canonical CSV serialization of the fault table (guaranteeing the exact input data can later be verified byte-for-byte); the resolved (post-truncation) distribution law for every bounded input; every configured mean/SD input parameter; the stress regime, orientation model, and per-input k values; and the installed Python, NumPy, pandas, SciPy, and Matplotlib versions, giving a complete, audit-ready provenance record for any exported analysis.

10. Visualization Components

The Monte Carlo tab exposes five distinct plotting environments (Geomechanics, Statistics, Sensitivity, Visualization, and Spatial Probability Map), each backed by an embedded Matplotlib figure (FigureCanvasTkAgg) and each offering a Save Image button that writes a PNG at the DPI configured in the application's export settings.

10.1 Geomechanics Sub-Tab Plots

10.1.1 Mohr Uncertainty Diagrams

When Use effective principal stresses is on, every circle is shifted left by its own realization's pore pressure (so the plot title reads "Mohr diagram for effective stress and pore-pressure variations"); an Include total-stress circles option can overlay the unshifted ensemble in grey behind the effective-stress circles for direct visual comparison of how much pore pressure moves the system toward failure.

10.1.2 Total-Stress Mohr Circles

10.5 Spatial Probability Map Sub-Tab

This sub-tab is unique among the six in requiring a second, independently loaded data source: a coordinate file (Excel/CSV) mapping each fault_id to either a single X/Y point or an X1/Y1–X2/Y2 trace segment, matched against the Monte Carlo results by ID. Column-alias detection accepts numerous header variants (Easting/Northing, bracketed unit suffixes such as "X [km]", etc.) and automatically infers the coordinate unit from the header text when possible.

Once coordinates are loaded, the module aggregates the realization population per fault_id into Fsi (mean Coulomb Failure Index), P10, P50, P90, and P(Fsi ≥ 1) (the fraction of realizations exceeding the failure threshold), computes an Uncertainty_Width = P90 − P10 metric, and offers three views:

  • Map Plot — a georeferenced scatter (point mode) or line-collection (trace mode) map colored by the selected metric, with a coordinate-unit conversion pipeline (km/m/cm/mm), optional fault-ID text labels, and a positionable colorbar.
  • Data Table — a scrollable tabular preview of the merged coordinate/probability data (capped at 500 rows for UI responsiveness), exportable to Excel or CSV independently of the main Validation & Export sub-tab.
  • Fracture Uncertainty Map — a horizontal bar chart ranking every fault by Uncertainty_Width, auto-sized (up to 60 inches tall) so that large fault populations remain legible without overlapping labels, with an optional numeric value annotation on each bar.
Note: the coordinate file's ID column must match the Fault ID values used in the original Monte Carlo input spreadsheet; any mismatched IDs on either side are reported by count in a dedicated warning banner rather than silently dropped.

11. Advanced Features

11.1 Move Layout Elements (Edit Mode)

A shared workspace-level Edit Mode toggle (in the WorkspaceHeaderMixin, invoked identically across all six sub-tabs) makes every plot legend draggable and enables free repositioning of plot axes by mouse drag. When engaged, matplotlib's constrained/tight layout engine is disabled for the affected figure (figure.set_constrained_layout(False)) so that manually dragged axis positions are not immediately overridden on the next redraw; twinned axes (e.g. a histogram's count axis paired with a response-trend axis) are detected by comparing bounding-box positions and moved together as a group so overlays stay aligned.

11.2 Manual Plot Pixel Sizing

Every sub-tab's Plot Appearance card exposes a Plot size (px) width/height control pair with an Apply Plot Size button (plot_size.apply_plot_pixel_size). This resizes the embedded Tk canvas widget directly (clamped to the range 240–4096 px per dimension), letting a user produce a figure at an exact pixel footprint suitable for a specific publication template or presentation slide, independent of the surrounding window size.

11.3 Custom Typography and Font Propagation

The shared workspace header's font family, size, weight, italic, and color controls (in uncertainty_app.py) are applied not only to the surrounding Tk UI but are actively re-applied to every Matplotlib artist — titles, axis labels, tick labels, legend text, and colorbar labels — across every registered figure in every sub-tab (_apply_uncertainty_figure_fonts), ensuring visual consistency between the on-screen application chrome and the exported plot images.

11.4 Worksheet Selection for Multi-Sheet Workbooks

Described in Section 4.1; this is implemented as a lightweight modal dialog rather than a silent "first sheet wins" default, preventing a common source of user error when a spreadsheet contains multiple related tabs (e.g. a raw-data sheet alongside a summary sheet).

11.5 Cross-Fault Result Caching and Restoration

Described further in Section 12.1; from the user's perspective, this surfaces as near-instantaneous switching between the All Faults view and any individual fault once at least one run has completed, along with a status-bar message ("Restored previously simulated results for …") confirming that cached data, not a fresh simulation, is being displayed.

11.6 Session Save/Restore and Cross-Module Isolation

The complete Monte Carlo session — loaded input file, every sidebar setting, and (implicitly, via autosave) the most recent results — is persisted per-project and reloaded automatically when the project is reopened, independent of whatever Static or Dynamic Analyzer state exists for the same project (Section 8.5).

12. Performance Optimization

12.1 Fault-Level Result Caching

fault_result_cache is a dictionary keyed by fault-selection label, storing the (results, validation_report) tuple produced by every completed run. When the user selects an individual fault that has no direct cache entry but an All Faults run has already been completed, _cached_fault_results_from_all_fault_run() slices that population by fault_id, recomputes only the lightweight convergence table and metadata for that subset, and caches the result — avoiding an entirely new (and computationally redundant) simulation. Loading a new input file or changing the sampling settings invalidates this cache, since a newly loaded source may reuse an existing Fault ID label that would otherwise return stale results.

12.2 Active-Tab-Only Redrawing

refresh_active_module() redraws only the Matplotlib figure(s) belonging to the currently visible module sub-tab; the other five sub-tabs' plots are refreshed lazily, the first time each becomes visible after new results arrive. This avoids six simultaneous, expensive Matplotlib redraws (including scatter re-rendering, colorbar reconstruction, and legend layout) every time a simulation completes or a fault is switched.

12.3 Debounced Appearance-Setting Redraws

Because many appearance controls (color swatches, sliders, dropdowns) can fire several rapid variable-write events in a single user interaction (e.g. a color picker emitting intermediate values while being dragged, or Reset to Defaults setting ~30 variables at once), every sub-tab coalesces these bursts into a single scheduled redraw roughly 60–80 milliseconds after the last change, using Tk's after()/after_cancel() scheduling primitives. This eliminates visible flicker and avoids redundant full figure.clear()-and-rebuild cycles.

12.4 Threaded I/O and Computation

File loading (Section 4), coordinate loading for the Spatial Probability Map (Section 10.5), and the Monte Carlo sampling/validation pipeline itself (Section 8.2) all execute on background daemon threads, with results marshaled back to the Tk main thread via widget.after(0, callback). This keeps the application's event loop responsive — including allowing the Cancel control to be clicked — throughout potentially long-running operations.

12.5 Vectorized Stability Calculation

calculate_fault_stability() operates on entire NumPy arrays of realizations at once (rather than looping in Python per realization), so the per-realization cost of Equations 6.1–6.11 is amortized across the whole ensemble via compiled array operations — essential for keeping sample sizes up to 100,000 responsive.

12.6 Bounded Mohr-Circle Rendering

The Geomechanics sub-tab's Mohr uncertainty diagrams cap the number of individually rendered circles (Max. displayed circles, default 900) by selecting evenly spaced representative realizations from the full ensemble via a linear index subsample, rather than rendering one Matplotlib LineCollection segment per realization — preventing the plot from becoming sluggish or visually saturated at large sample sizes while preserving a representative visual impression of the full distribution.

12.7 Scrollable Auto-Sizing for Large Fault Populations

The Fracture Uncertainty Map (Section 10.5) dynamically grows its figure height (up to 60 inches) in proportion to the number of faults, embedded inside a scrollable Tk frame, only recalculating this size when the fault count itself changes (not on every cosmetic appearance edit) — avoiding both label overlap for large fault populations and unnecessary canvas reconfiguration during routine styling adjustments.

13. Practical Examples

13.1 Example 1 — Single Representative Fault Screening

Scenario: A geomechanical analyst has measurement uncertainty on a single, poorly constrained fault plane (Strike 45° ± 5°, Dip 60° ± 5°) and wants a rapid screening estimate of reactivation risk under current reservoir stress conditions, without loading a spreadsheet.

  1. Open the Monte Carlo Simulation tab without loading any input file; the sampler falls back to the built-in representative plane (Section 4.3).
  2. In Geomechanics, set the Stress Regime to Reverse/Thrust (Sv = S3), enter the site's principal-stress means/SDs and distributions, and confirm Friction, Cohesion, and Pore Pressure means reflect the best available core or offset-well data.
  3. Set SAMPLES to 5000 and SEED to any fixed integer for reproducibility, then click Run Monte Carlo Simulation.
  4. Inspect the Geomechanics sidebar's Probability of Failure tile and the Mohr uncertainty diagram; a cluster of sampled circles crossing the Coulomb envelope indicates meaningful reactivation risk even if the mean case appears stable.
  5. Open Sensitivity to identify which input (e.g. pore pressure or friction) contributes most to the spread in Fsi, focusing further data-acquisition effort on that parameter.

13.2 Example 2 — Population-Level Injection Risk Screening

Scenario: A CO₂-injection or produced-water-disposal operator has a spreadsheet of 40 mapped faults (with Strike, Dip, and per-fault Sigma columns) and needs to rank faults by injection-induced reactivation risk under an anticipated pore-pressure increase.

  1. Load the fault spreadsheet via the workspace header's Load Excel control; confirm the Analysis columns selected dialog correctly matched every expected column.
  2. In Geomechanics, set FAULT to All Faults, enable Use effective principal stresses, and set the Pore Pressure mean to the anticipated post-injection value (with an SD reflecting monitoring/interpretation uncertainty).
  3. Run the simulation with a moderate sample size (e.g. 2000 per fault) suitable for 40 faults × 2000 = 80,000 total realizations.
  4. In Visualization, select the Fault-Level Uncertainty Envelopes layout to view all faults' Ts/Td/Sf/Fs P10–P90 envelopes and the Fault Behaviour Classification scatter simultaneously.
  5. Load the corresponding coordinate file in Spatial Probability Map and select P(Fsi ≥ 1) as the Display Variable to produce a map directly identifying the highest-risk fault locations for stakeholder communication.
  6. Export the full validated result set (Section 9.6) via Validation & Export → Export Excel for the permanent project record.

13.3 Example 3 — Comparing Von Mises and Fisher 3D Orientation Models

Scenario: An analyst wants to test whether treating strike and dip uncertainty as coupled (Fisher 3D) rather than independent (Von Mises) materially changes the predicted probability of failure for a critically oriented fault.

  1. Run the simulation once with Orientation Distribution set to Von Mises and a fixed seed, recording the resulting Probability of Failure and Ts P10–P90 range from the Statistics sub-tab.
  2. Switch Orientation Distribution to Fisher 3D (leaving every other setting, including the seed, unchanged) and re-run.
  3. Compare the two Ts histograms side by side (Statistics sub-tab) and the two Orientation Stereonet plots (Visualization sub-tab) to visualize how the coupled Fisher model reshapes the sampled orientation cloud relative to the independent Von Mises model.

14. Geological and Engineering Interpretation

14.1 Reading Slip Tendency (Ts)

A realization's Ts should be compared against an appropriate frictional threshold; Byerlee's Law suggests typical crustal rock friction coefficients cluster near μ ≈ 0.6–0.85, so Ts values approaching or exceeding roughly 0.6 in the sampled population indicate that a meaningful fraction of plausible stress/strength combinations places the fault near or past frictional failure. The Monte Carlo population view is essential here: a deterministic mean-case Ts below the threshold can still coexist with a substantial P90 tail above it, meaning failure is a real (if not certain) possibility rather than a remote one.

14.2 Reading Dilation Tendency (Td)

High Td (approaching 1) identifies fault or fracture orientations most favorably aligned for hydraulic opening (dilation) under the current stress field — geologically significant for identifying preferential fluid-flow pathways, potential conduits for fault-controlled mineralization, or, in an injection context, faults most susceptible to opening-mode reactivation rather than pure frictional slip.

14.3 Reading Fracture Susceptibility (Sf) and the Coulomb Failure Index (Fsi)

Sf provides a physically interpretable stress margin in MPa — the amount by which normal stress would need to change (holding shear stress, friction, and cohesion fixed) to bring the fault exactly onto the failure envelope. Fsi, being dimensionless and normalized so that 1.0 always marks the failure envelope regardless of the specific friction/cohesion values, is generally the preferred metric for comparing relative risk across faults with different strength properties, as is done in the Fault Behaviour Classification plot's fixed 0.80 Fsi threshold for the "Critically Stressed" category.

14.4 Effect of the Effective-Stress Toggle on Interpretation

Disabling Use effective principal stresses produces a conservative, total-stress-only assessment appropriate for a baseline geological characterization where current pore pressure is either unknown or intentionally excluded from the stability question. Enabling it is essential whenever the analysis question specifically concerns fluid-pressure-driven reactivation (injection, depletion, or natural pore-pressure evolution), since Terzaghi effective-stress theory is the physically correct basis for assessing frictional failure in a fluid-saturated rock mass.

14.5 Stress Regime Selection and Its Geological Basis

The stress-regime selector (Sections 5.1, 6.4) should be set according to independent evidence for the tectonic regime at the site of interest (e.g. from World Stress Map compilations, borehole breakout analysis, or regional structural geology), not chosen arbitrarily; an incorrect regime assignment will systematically misplace the vertical stress within the fault-normal-stress calculation and can materially bias every downstream metric.

14.6 Orientation Model Selection and Its Geological Basis

Von Mises independent sampling is appropriate when strike and dip uncertainty genuinely originate from separate, uncorrelated sources (for example, strike picked from a seismic horizon and dip estimated separately from an image log in a different well). Fisher 3D coupled sampling is appropriate whenever the orientation uncertainty is inherently a single combined angular measurement uncertainty (for example, a single planar feature interpreted from one borehole-image or outcrop measurement), since the Fisher distribution correctly represents uncertainty as a cone around one 3-D pole direction rather than as two independent linear wobbles.

15.2 Numerical Stability Safeguards

  • The shear-stress radicand in Equation 6.5 is clamped to a minimum of zero to prevent NaN results from floating-point rounding near zero shear.
  • Every distribution transform in sample_scalar() clips its unit-uniform input to the open interval (1×10⁻¹², 1−1×10⁻¹²) before applying an inverse-CDF, preventing infinite quantile values at the extremes.
  • Denominators in Ts, Td, Sf, and Fs are guarded with explicit validity masks (e.g. calculation_normal > 0, friction_valid, dilation_valid) so that an invalid realization yields a reported missing value rather than a divide-by-zero exception or a silently wrong number.
  • The principal-stress gap-variance construction (Equation 7.3) clamps its radicand to zero rather than allowing a negative variance under a (validated-against) inverted SD ordering.

15.3 Threading Model Summary

All Tkinter widget mutations occur exclusively on the main thread; every background thread (file loading, simulation, coordinate loading) communicates results back via widget.after(0, callback), and every long-running loop checks a shared threading.Event for cooperative cancellation at well-defined checkpoints rather than being forcibly terminated.

15.4 Data Model Summary

The canonical realization table produced by generate_samples() is a single pandas DataFrame with one row per (fault, realization) pair, carrying columns for every sampled input (sigma1–sigma3, friction, cohesion, pore_pressure, shmax, strike, dip), the derived stability outputs (normal_stress, effective_normal_stress, shear_stress, Ts, Td, Sf, Fs, failure), and identifying columns (fault_id, realization). Provenance and configuration are attached as DataFrame .attrs metadata (stress_regime, distribution_settings, configured_distributions, effective_distributions, orientation_distribution, orientation_k_by_input, use_effective_ts, slip_tendency_stress_basis) rather than as additional data columns, keeping the tabular export clean while preserving full reproducibility.

16. Limitations

LimitationDescription
Idealized fault geometryThe underlying stability physics assumes planar, non-intersecting fault surfaces with spatially uniform stress and strength properties per realization; fault-zone heterogeneity, curvature, and stress perturbation near fault tips are not modeled.
Independent inputsInputs other than fault orientation are assumed statistically independent of one another; correlated uncertainty between, for example, cohesion and friction (common in some laboratory-derived strength envelopes) is not natively supported and would require an external pre-transformation of the input distributions.
Linear failure criterionThe Mohr–Coulomb failure criterion is linear in normal stress; non-linear (e.g. Hoek–Brown or Barton–Bandis) failure envelopes are not implemented.
First-order sensitivity measuresSensitivity coefficients (SRC, PRCC) are regression-based, global, first-order measures; they do not capture higher-order interaction effects between inputs, and SRC specifically assumes an approximately linear input-output relationship.
Convergence is a heuristicThe 2% / 1-percentage-point convergence criterion (Section 9.4) is a practical heuristic, not a formal statistical stopping rule; a run reported as "Passed" does not guarantee that every downstream statistic (e.g. an extreme tail percentile) has fully converged.
Exact-ID coordinate matchingThe Spatial Probability Map requires exact string-matched Fault IDs between the Monte Carlo input spreadsheet and the separately loaded coordinate file; no fuzzy or coordinate-based automatic matching is performed.
Sample-size capMaximum sample size is capped at 100,000 realizations per fault by UI validation; very large multi-fault populations (many faults × large sample counts) are bounded primarily by available system memory and interactive redraw performance rather than by an explicit software limit.
Single-parameter Fisher couplingThe Fisher 3D orientation model couples strike and dip using a single shared concentration parameter (from the Strike row); it does not support independently specified strike and dip concentrations within the coupled model.
