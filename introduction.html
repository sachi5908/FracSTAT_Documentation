Why We Need FracSTAT

Quantitative characterization of fracture networks has become an indispensable component of structural geology, rock mechanics, and reservoir characterization. These networks exert fundamental control over the mechanical, hydraulic, and transport properties of rocks (National Research Council, 1996), which in turn influences critical factors like fluid migration (Berkowitz, 2002), reservoir productivity, geothermal circulation, groundwater flow, mineralization, and the long-term integrity of subsurface engineering systems. Because fracture populations are commonly scale-dependent, their length, spacing, and aperture distributions must be characterized statistically rather than described by single representative values (Bonnet et al., 2001), and both mechanical and chemical processes contribute to the patterns that are ultimately measured (Laubach et al., 2019).

The Fragmentation Problem

Despite significant advancements in software development over the past decade, the process of analyzing fracture networks often remains fragmented across multiple environments. Existing open tools each cover part of the problem well — trace-pattern quantification in FracPaQ (Healy et al., 2017), topological and geometric network analysis in NetworkGT (Nyberg et al., 2018), and spherical projection in OSXStereonet (Cardozo & Allmendinger, 2013) — but no single environment carries a dataset through all of them. This creates several bottlenecks for researchers and engineers:

  • Digitization, topological analysis, statistical analysis, stress evaluation, and uncertainty quantification are frequently performed in entirely different software packages or through custom scripts.
  • This disjointed workflow requires unnecessary data transfer, repeated preprocessing, and leads to inconsistent parameter handling.
  • It severely limits reproducibility and creates a steep learning curve, especially for students or researchers without extensive scientific programming experience.
  • Many of these fragmented workflows rely on proprietary software environments, making comprehensive fracture characterization both technically demanding and time-consuming.

The FracSTAT Solution

FracSTAT is not designed to simply replace existing software, but to provide a cohesive, open-source, and user-oriented computational framework that unifies these critical analytical components into a single application. Key benefits include:

  • Integrated Workflow: It combines geometric analysis, statistical characterization, spatial analysis, network topology (Sanderson & Nixon, 2015), visualization, stress-based fracture assessment (Morris et al., 1996), and uncertainty quantification into a consistent, reproducible pipeline.
  • Seamless Data Utilization: Information generated in one module is smoothly transferred and utilized by subsequent modules, minimizing manual intervention and ensuring methodological consistency.
  • Open-Source Accessibility: FracSTAT is completely Python-based and open-source, building on NumPy (Harris et al., 2020), SciPy (Virtanen et al., 2020), pandas (McKinney, 2010), and Matplotlib (Hunter, 2007), which removes the reliance on proprietary tools. It features a graphical user interface (GUI) that allows for advanced analysis without requiring deep programming expertise.
  • Extensible Architecture: While accessible to beginners, its modular design provides advanced users with the flexibility to extend the software's capabilities as new research challenges arise.
  • Uncertainty Quantification: Modern geological investigations require more than deterministic measurements. FracSTAT answers this by incorporating rigorous quantification of uncertainties through Monte Carlo and Latin hypercube sampling (McKay et al., 1979); Helton & Davis (2003), with global sensitivity measures (Saltelli et al., 2008), and evaluating their implications for geomechanical interpretation directly within the workflow.

Ultimately, FracSTAT serves as an integrated analytical platform intended to bridge the gap between conventional fracture characterization and modern quantitative structural analysis. It delivers a transparent, extensible framework to investigate all facets of a fracture network within one unified environment.

User Interface Technology

FracSTAT's desktop interface is built on PySide6 (Qt for Python). Plots are native Matplotlib figures embedded through Matplotlib's backend_qtagg Qt canvas.

Note for readers of the module pages: the widget classes named throughout this documentation — CTkFrame, CTkTabview, CTkScrollableFrame, FigureCanvasTkAgg, StringVar, ttk.Treeview, and the after() scheduling calls — are provided by FracSTAT's own ui_common.qtk layer. This layer keeps a familiar Tk-style API surface while implementing every widget on top of PySide6 (for example, ttk.Treeview is a QTreeWidget subclass and after() is driven by QTimer). These names therefore describe Qt widgets, not CustomTkinter or Tkinter ones.

How to cite FracSTAT. If any part of an analysis in a publication was produced with this software, cite the application itself in addition to the method sources listed on the individual tab pages:

Mahanta, S. N., Kumar, P. C., Srivastava, E., Kumar, J., Rizzo, G. F., Gasparo Morticelli, M., Sulli, A., & Sain, K. (2026). FracSTAT: an integrated open-source platform for fracture statistics, stress-based and uncertainty analysis (Version 1.0.0) [Computer software]. https://github.com/sachi5908/FracSTAT

Also state the FracSTAT version (shown as the badge below the launcher logo, and in full on the in-app About page), the Python version, and whether the analysis was run from source or from the standalone desktop build — the version number is what fixes the algorithms and defaults a reader would need to reproduce a figure. Each tab page carries its own methods statement naming the estimators, conventions and parameter values that page's plots depend on; cite those in the methods section rather than citing this page alone.
