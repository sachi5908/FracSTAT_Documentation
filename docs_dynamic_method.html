Dynamic Method Tab

Located at dynamic_analyzer/tabs/dynamic_method_tab.py, the Method tab (implemented as the mixin class MethodTab) is the Dynamic Analyzer's built-in, read-only reference sheet. Unlike every other tab in the Dynamic Analyzer, it consumes no project data and produces no plot — it exists purely to document, in one place, the exact geometric and stress-mechanical formulas that the Map, Rose, Mohr, and Table tabs apply to every loaded fracture segment. It is the single source of truth a user can check to confirm precisely how a reported stress angle, slip tendency, or Coulomb failure state was derived.

1. Interface Overview

The Method tab occupies the full width of its workspace tab with a single scrollable CTkTextbox widget, padded 20 px on every side to give the text a clean, card-like appearance. There is no sidebar, no plot canvas, and no interactive control of any kind — the widget is explicitly locked to a read-only (state="disabled") state immediately after its content is inserted, so the tab behaves purely as documentation rendered inside the application itself rather than as an analysis surface.

2. Purpose and Scope

Every other tab in the Dynamic Analyzer — Map, Rose, Mohr, Stereonet, and Table — resolves stress onto fracture planes and reports derived quantities such as slip tendency, dilation tendency, susceptibility, and Coulomb failure state, but none of them re-explain the underlying formulas at the point of use. The Method tab exists to close that gap: it is a static, in-application reference that a user can open at any time to see, in order, exactly how raw SVG geometry is turned into a scaled fracture network, how that network's strikes are corrected to true North, how the stress angle to each fracture is computed, how normal and shear stress are resolved via the 2-D Mohr transformation, and how each of the tendency and failure metrics reported elsewhere in the workspace is defined.

Because the tab performs no calculation of its own — it only documents calculations performed by other tabs — it has no data-input requirements, no settings, and no redraw logic. Its entire behaviour is determined once, at tab-build time, by the sequence of text.insert() calls in _build_method_tab().

3. Content Structure and Typography

The tab uses the ui_common.qtk text-widget tag API to give the reference sheet a typographic hierarchy without resorting to a rich-text or HTML rendering engine. Four fonts and five tags are defined once at build time and then applied selectively as each line is inserted.

4. Mathematical Background

The reference sheet proceeds through five formula-bearing sections, in the same order every other Dynamic Analyzer tab implicitly relies on: geometry construction, profile scaling and strike correction, the stress angle definition, the resolved-stress transformation, and the tendency/failure metrics computed from that resolved stress.

4.1 Geometry

Every digitised SVG trace is converted into one or more straight fracture segments before any stress calculation begins. A line primitive in the source SVG becomes exactly one segment; curved primitives are sampled into a series of shorter straight segments according to the workspace's Curve step setting, exactly mirroring the tessellation approach used by the Static Analyzer's geometry engine. Every resulting segment — whether from an originally straight or originally curved trace — is treated identically and calculated independently by every downstream stage.

4.2 Profile Scaling and Strike Correction

Raw SVG coordinates exist only in arbitrary digitiser pixel units. FracSTAT rescales the full coordinate extent of the loaded trace map onto the physical Profile Width and Profile Length supplied by the user, in metres, so that every plotted X/Y coordinate and every reported segment length is expressed in the currently selected display unit rather than in raw pixels. Because the horizontal and vertical scale factors are computed independently from the profile width and length respectively, non-square profiles (where width and length differ) are still handled correctly — the rescaling is not assumed to be uniform in both directions.

Segment strike, as measured directly from the SVG geometry, is referenced to the image's own Y axis rather than to true geographic North. The Image Y-axis azimuth setting, θ, records how far that image Y axis is rotated away from true North, and every raw image strike is corrected by this offset before it is used anywhere else in the workspace:

strike_N = image strike + θ

4.3 Fracture-Plane Normal and Stress Angle

The maximum principal stress σ₁ is supplied as an azimuth measured from true North (or, in fully orthogonal 3D mode, as its own trend and plunge — see below). FracSTAT does not resolve stress directly onto the fracture plane's strike direction; it resolves stress onto the plane's pole, or outward normal, which is built from the corrected strike and the fracture's dip in an (East, North, Up) basis:

n = ( sin(dip)·sin(strike_N + 90°), sin(dip)·cos(strike_N + 90°), cos(dip) )

The normal's vertical component depends directly on dip: a vertical fracture (dip = 90°) has a purely horizontal normal, while a shallowly dipping fracture's normal points mostly upward. The stress angle α reported throughout the app is the angle between this normal and the σ₁ axis, α = arccos(|n·σ̂₁|) — dip therefore already enters the calculation at this first stage, not just the resolved-stress step that follows.

4.4 Resolved Stress

With the normal n defined above, FracSTAT projects each of the three principal stresses onto n and recombines them into the resolved normal and shear stress. In the default Andersonian mode (σ₁ and σ₃ horizontal, σ₂ vertical), the three direction cosines are:

c₁ = n · σ̂₁ (horizontal component, along the σ₁ azimuth) c₂ = n_z (vertical component of n — i.e. along σ₂) c₃ = n · σ̂₃ (horizontal component, perpendicular to σ₁)

and the resolved stresses follow from:

σₙ = σ₁c₁² + σ₂c₂² + σ₃c₃² τ = √( σ₁²c₁² + σ₂²c₂² + σ₃²c₃² − σₙ² )
This is a full 3D transformation, not a 2D one. Unlike a plane-stress formula written purely in terms of σ₁, σ₂ and α, both σₙ and τ here depend on dip (through c₂) and on all three principal stresses, not just two of them. A vertical fracture (dip = 90°) has c₂ = 0, which removes σ₂ from the calculation entirely and reduces the problem to two stress axes; as dip decreases from vertical, σ₂ increasingly contributes to the resolved stress. Two fractures with the same strike and stress angle α but different dip will, in general, be resolved onto different (σₙ, τ) points — dip is not a free parameter that can be ignored when checking a reported value by hand.

This is implemented as stress_on_plane_3d() in core/models.py. When a fully orthogonal (non-Andersonian) stress frame is supplied instead — i.e. σ₁ trend/plunge and σ₃ trend/plunge are entered directly rather than just a σ₁ azimuth — the same σₙ/τ formulas are used, but c₁, c₂, c₃ become the normal's dot products with three independently oriented unit axes rather than being tied to the horizontal‑σ₁/σ₃, vertical‑σ₂ assumption; this variant is stress_on_plane_3d_general().

Which principal stress is vertical is an explicit parameter, not a hidden assumption. stress_on_plane_3d() and the helper that builds the axes, andersonian_principal_axes(), both take a vertical_axis argument selecting the Andersonian regime (Anderson, 1951): "sigma1" for normal faulting (Sv = σ₁), "sigma2" for strike-slip (Sv = σ₂), "sigma3" for reverse/thrust (Sv = σ₃). The default is "sigma2", which is exactly what the Dynamic Analyzer's Andersonian Model (Simplified) mode documents and what the c₂ = n_z identification above relies on — so in that mode σ₂ is the vertical axis and the remaining horizontal axis lies 90° clockwise from the σ₁ azimuth. The parameter exists because the Uncertainty Analyzer resolves stress on the opposite default convention (Sv = σ₃; see its _remap_for_regime helper, which permutes the calculator's σ₁/σ₂/σ₃ inputs per regime). The two subsystems therefore answer different questions unless the same regime is selected in both, and slip tendency computed under the wrong regime can differ by more than a factor of two. For any regime other than strike-slip, either pass vertical_axis explicitly or supply a fully orthogonal frame and use stress_on_plane_3d_general().

4.5 Tendency Metrics

Four derived quantities, each computed directly from the resolved σₙ and τ of Section 4.4, are reported throughout the Dynamic Analyzer's Map, Rose, and Table tabs:

SymbolNameFormula
TsSlip tendencyTs = τ / σₙ (Morris et al., 1996)
TdDilation tendencyTd = (σ₁ − σₙ) / (σ₁ − σ₃) (Ferrill and Morris, 2003)
SfSusceptibility / fracture stability marginSf = σₙ − Pᶠ − (τ − C₀) / μ (Mildren et al., 2002; Streit and Hillis, 2004)
CSFCritical stress flagTrue where τ ≥ μ(σₙ − Pᶠ) + C₀ (Jaeger et al., 2007)

Here Pᶠ is pore-fluid pressure, C₀ is cohesion, and μ is the coefficient of friction — the same three Coulomb failure-envelope parameters used to draw the failure line on the Mohr diagram. Slip tendency Ts is the ratio of resolved shear to resolved normal stress and increases toward frictional failure; dilation tendency Td measures how close a fracture's normal stress sits to the least principal stress σ₃, with values near 1 indicating a fracture oriented favourably for opening-mode dilation; the susceptibility/stability margin Sf and the boolean CSF flag both express distance from, or crossing of, the effective-stress Coulomb failure envelope.

Sf is reported directly in the working stress unit, not on a 0–1 scale, and has a physical reading: it is the additional pore-pressure increase the plane can sustain before the effective-stress Coulomb envelope is reached (Mildren, Hillis and Kaldi, 2002; Streit and Hillis, 2004). Written as Sf = σₙ′ − (τ − C₀)/μ with σₙ′ = σₙ − Pᶠ, that reading is explicit: a large positive value means a large pressure margin, Sf = 0 means the plane is already critically stressed, and a negative value means it sits beyond the envelope. Because the quantity is a pore-pressure increment, the pore-pressure term is always subtracted in Sf — unlike Ts and Td, which are reported on total σₙ.

core/calculator.py actually computes a second susceptibility value alongside Sf: FractureSusceptibilityLegacy, matching the original (pre pore-pressure-correction) reference-script formula Sf,legacy = σₙ − τ/μ. The two differ by exactly Pᶠ when cohesion is zero. Only the corrected Sf above feeds the app's own colour-by and Mohr-field options; the legacy value is carried through for cross-checking against older reference output and appears as its own column in the Table tab.

Two further columns are derived once the whole segment table exists, because the colour scales in the Map, Rose, Mohr and Stereonet tabs need a bounded 0–1 quantity:

Ts,norm = Ts / Ts,max with Ts,max = (σ₁ − σ₃) / ( 2·√(σ₁·σ₃) ) Sf,norm = 1 − ( Sf − min Sf ) / ( max Sf − min Sf )
Ts,max is theoretical, not the largest loaded value. The reference MATLAB script obtains Ts,max by scanning τ/σₙ over a dense grid of every possible fracture orientation, not over the fractures actually loaded from file. For a diagonal principal-stress tensor that maximum has the closed form shown above — the tangent from the origin to the outer σ₁–σ₃ Mohr circle — and depends on σ₁ and σ₃ alone: not on σ₂, not on the principal-axis orientation, and not on which poles were digitised. _theoretical_max_slip_tendency(σ₁, σ₃) returns that value, so SlipTendencyNorm reproduces the reference Ts to numerical precision. Normalising by df["SlipTendency"].max() instead — the maximum among the loaded fractures — only agrees by coincidence, when the loaded set happens to contain a plane at or near the optimal orientation; otherwise every normalised value is inflated by the ratio of the two maxima. Where σ₃ ≤ 0 (tensile or effective-stress states whose Mohr circle reaches the origin) the radicand is floored proportionately to the stress magnitude, at 10⁻⁶·max(σ₁², 1), rather than at an absolute constant, so Ts,max stays finite without collapsing every normalised value toward zero.
Sf,norm is deliberately inverted. Because a smaller Sf means a smaller remaining pressure margin, i.e. a plane closer to failure, the min–max rescaling is subtracted from 1 so that the most susceptible planes (lowest Sf) map to 1.0 — the "hot" end of every colour ramp — and the most stable planes map to 0.0. Without the inversion the Map, Rose, Mohr and Stereonet colour scales render stable planes as critical and critical planes as stable. If every segment shares the same Sf (range below 10⁻¹²), the column is set to 0.0 rather than dividing by zero. Note that this rescaling is dataset-relative: unlike Ts,norm, Sf,norm = 1.0 does not mean failure, only "the least stable plane in this file", so it should not be compared between datasets.

5. Implementation: How the Text Is Built

_build_method_tab() runs once, when the Method tab is constructed, and performs no further work afterward — there are no callbacks, no variable bindings, and no redraw path, since nothing on the tab can be edited or reconfigured by the user.

  1. Grid-configure the tab's single row and column to expand, and place one CTkTextbox with 20 px internal padding so the text reads as a padded card rather than touching the tab's edges.
  2. Construct the four named CTkFont objects (title, header, body, math) plus the smaller subscript font, all in the Roboto family for prose and Consolas for formulas.
  3. Register five tags on the textbox's underlying Text adapter (text._textbox), each carrying its own font, spacing, indentation, and (for title) centre justification.
  4. Insert the page title, then each section heading and its body/formula content in sequence, using the appropriate tag or tag-tuple for every inserted run of text.
  5. For the three subscripted tendency-metric symbols, insert the base letter, the subscript character, and the remainder of the line as three separate calls so the subscript renders at reduced size and lowered baseline.
  6. Call text.configure(state="disabled") as the final step, permanently locking the widget against further editing while leaving it fully scrollable and selectable for copying.
python 
text._textbox.tag_config("math", font=font_math, lmargin1=30, lmargin2=30, spacing1=5, spacing3=15)
text._textbox.tag_config("sub", offset="-4", font=font_math_sub)

# T_s, rendered as three separate inserts so the "s" renders as a
# smaller, baseline-shifted subscript within an otherwise monospaced line
text.insert("end", "T", "math")
text.insert("end", "s", ("math", "sub"))
text.insert("end", " = τ / σₙ\n", "math")

# Lock the widget once every section has been inserted
text.configure(state="disabled")

6. Focal-Mechanism Mode

The final section of the reference sheet documents a distinct data pathway that the rest of the Dynamic Analyzer treats transparently: Excel/CSV files carrying Lat, Lon, FP1 Strike/Dip and, optionally, FP1/FP2 Slip columns are recognised as earthquake focal-mechanism data rather than digitised fracture traces. Each supplied nodal plane becomes its own segment, after which the Map tab plots the event at its true Lat/Lon location and can display the corresponding GlobalCMT-style beachball diagram, fetched from the file's Beachball URL column, for whichever event is currently selected.

When a Slip (rake) value is supplied for a nodal plane, FracSTAT goes beyond simple stress resolution: it projects the resolved shear traction onto the true three-dimensional slip vector constructed from that plane's strike, dip, and rake, following the Wallace–Bott hypothesis that slip occurs parallel to the resolved shear stress on the fault plane (Wallace, 1951; Bott, 1959). The angular difference between the observed slip direction and the direction the entered stress tensor predicts is reported as the Rake Misfit — a low misfit indicates that the assumed stress state is kinematically consistent with the recorded earthquake, while a high misfit suggests the entered principal stress orientation and/or ratio should be reconsidered.

Rake sign convention: rake is interpreted in the standard convention of Aki and Richards (1980, §4.2), as used by the GlobalCMT catalogue — measured within the fault plane from the strike direction, positive towards the up-dip direction, so that rake = 0° is left-lateral, +90° is pure thrust, 180° (or -180°) is right-lateral, and -90° is pure normal faulting. The slip vector is therefore built as u = cos(rake)·ŝ + sin(rake)·û, where ŝ is the unit strike vector and û the unit up-dip vector. Because FracSTAT enters principal stresses as compression-positive magnitudes, the Cauchy traction built from them is negated before the shear component is extracted, so that the resolved shear vector points in the sense the hanging wall is driven to move. Predicted Rake is reported in the same convention as the input, which means rake values taken directly from a GlobalCMT-style catalogue can be compared with it without any sign or reference-direction conversion.
Backward compatibility: older two-column focal-mechanism files containing only ID, Strike, and Dip continue to load and function exactly as before; the loader auto-detects which of the two schemas a given file uses without requiring any action from the user.

7. Relationship to Other Dynamic Analyzer Tabs

The Method tab's content is descriptive of, and consistent with, exactly what the rest of the workspace computes and displays:

Dynamic Analyzer TabWhat it uses from the Method tab's formulas
Map TabColours every segment by whichever tendency/failure metric (Ts, Td, Sf, or CSF) is currently selected, computed via Sections 4.3–4.5.
Rose TabBuilds a length-weighted, 10° binned, square-root (equal-area) polar histogram of the same corrected strike_N values described in Section 4.2, mirroring 0–180° strikes into the 180–360° half for full-circle display.
Mohr TabPlots total stress (σₙ, τ), effective stress shifted by pore pressure Pᶠ, individual segment points, and the Coulomb failure envelope τ = C₀ + μσₙ′ using exactly the resolved-stress formulas of Section 4.4; Mohr-diagram point numbers correspond directly to each segment's ID in the Table tab. The quantity Δτ = τ − [C₀ + μ(σₙ − Pᶠ)] is positive wherever a segment's Mohr point touches or crosses the failure envelope.
Table TabTabulates the per-segment numeric results (strike_N, α, σₙ, τ, Ts, Td, Sf, CSF) produced by the same pipeline documented here.
